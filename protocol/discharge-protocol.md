# 放电测量协议 v0.1

这份文档规定"怎么放完一次电"，让不同人、不同机器测出来的数能放在一张表里。
不按协议跑的数据，分析器不会拦你，但结论不可比。

---

## 0. 为什么要协议

电池容量不是一个固定常数，它同时受四个变量影响：温度、放电倍率、截止电压、电池老化程度。
不固定前三个，测出来的差异你分不清是电池坏了还是今天屋里冷。

所以协议只做一件事：**把前三个变量钉死，只留下你想测的那个**。

---

## 1. 环境准备

| 项目 | 要求 | 原因 |
|---|---|---|
| 环境温度 | 23–27 °C，全程波动 ≤ 2 °C | 低温容量缩水 10%+ 属于正常物理现象 |
| 放置方式 | 平放硬桌面，不要垫被子、不要握手里 | 散热条件一致才可比 |
| 飞行模式 | 开 | 蜂窝/WiFi 搜网功耗波动大 |
| 屏幕亮度 | 手动固定到 200 nit（约 50%），关自动亮度 | 屏幕是最大耗电项 |
| 省电/性能模式 | 全部关闭，用默认平衡模式 | 省电模式会限频降功耗 |
| 快充 | 拔掉充电器再开始，全程不充电 | 充电段的数据在充电 IC 之前，不可用 |
| 后台应用 | 清空，只留测量程序 | 后台唤醒不可控 |

> 温度这一项最容易糊弄自己。冬天在没有暖气的房间里测，容量掉 15% 是电池正常的物理表现，不是老化。

## 2. 起始状态

1. 关机充电到 100%，**继续插着充 1 小时**（让电池真正吃饱，不是"显示 100%"）。
2. 拔线，**静置 2 小时**。这一步是为了消掉表面电荷——刚拔线时电压虚高，直接放电会多算出几百 mAh。
3. 静置结束时记录：环境温度、起始 SOC（应为 100%）。

静置这两小时是整份协议里最容易被跳过、也最影响结果的一步。

## 3. 放电负载

目标是让功耗尽量平稳，不要忽高忽低——积分对功耗尖峰不敏感，但功耗曲线的形状会改变电池的实际输出容量。

### 推荐方案：本地视频循环

- 播放一段本地 1080p 视频，循环，音量 50%
- 屏幕常亮，亮度锁 200 nit
- 关闭弹幕、弹幕会引入网络与解码抖动

这个负载在多数旗舰上稳定在 3–5 W，波动小，且不需要 root、不需要外接设备。

### 更准的方案：外接 USB 电子负载

有条件的话，用可编程电子负载以恒功率 5 W 从电池取电，手机侧只负责记录。
这是唯一能拿到"绝对容量"的做法，软件负载只能拿到"协议内可比容量"。

### 不要用的负载

- 大型游戏：帧率波动导致功耗波动 ±50%
- 跑分软件：会把 CPU 拉到峰值并持续降频，曲线是锯齿
- 屏幕最高亮度 + 扬声器最大音量：温度会顶到温控墙，后半段测的是降频不是容量

## 4. 采集

放电开始的同时启动采集，一直到手机自动关机。

```bash
# 常规容量测量，1 Hz 足够
python runner.py run --design 5000 --interval 1

# 想顺便测内阻，用高频采样（阶跃只持续几十毫秒）
python runner.py run --design 5000 --interval 0.05
```

用 `--interval 0.05` 时文件会很大（4 小时约 28 万行），但能抓到电流阶跃，
算出直流内阻。内阻是判断老化的第二个独立证据：容量掉了但内阻没涨，可能是标定漂移；
内阻涨了 50% 以上，基本可以确认老化。

手机自动关机后：

```bash
adb pull /data/local/tmp/session.csv data/
python analyzer/cli.py data/session.csv --design 5000
```

## 5. 数据有效性自检

分析器会在报告末尾打印提示，出现以下任意一条，这次数据就别拿去跟别人比：

- [ ] 起始 SOC < 95% —— 没充满，容量偏低
- [ ] 结束 SOC > 10% —— 没放完，容量偏低
- [ ] 放电时长 < 30 分钟 —— 数据段太短，积分噪声放大
- [ ] 环境温度波动 > 2 °C —— 温度归一失效
- [ ] 电流读数缺失超过 5% —— 该机型 `current_now` 不可靠，要换采集方式

## 6. 重复性

同一天、同一环境，**同一台机器至少跑两次**，两次健康度相差应在 2 个百分点以内。
超过就说明协议没控住变量（最常见是温度没控住），先把环境板住再谈电池。
